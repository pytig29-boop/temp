### 1.1 실행 전에 알아야 할 코드 사실 3가지

1. **결선의 개발 구간 증거는 결선 시점에 다시 계산된다.** `final_verdict` 가 `Pipeline.campaign_stats()` 를 다시 불러 DSR 시도 수를
   `max(군집 수, 계열 시도 × 군집/스펙 수, 프로그램 시도 × 군집/스펙 수)` 로 잡는다. 따라서
   - `vol_breakout` 계열에 시도를 더하면 **기존 후보의 결선 증거가 조금 깎인다** → 트랙 ③ 은 최대 4건으로 묶는다.
   - 다른 계열의 시도는 프로그램 시도가 **102를 넘기 전까지** 기존 후보에 영향이 없다. R4 뒤 프로그램 시도는 최대 50 → 영향 없음. **프로그램 시도 100 을 넘기는 일은 이 주기에 하지 않는다**(넘길 것 같으면 중단).
2. **신호 선별의 귀무는 지금 "같은 KST 시각 × 변동성"으로 짝짓는다**(`signal_study.STRATIFY = hour_vol | hour | none`). 시각으로 정해지는 진입은 이 귀무와 정의상 같아져 초과가 0 이 된다. → 변동성만 맞추는 층 `vol` 을 추가해야 한다(§4 작업 1.2). `signal_study.py` 는 규칙 묶음(`rs-003` 구성 파일)에 **들어 있지 않다** — 고쳐도 잠금 해시는 안 바뀐다. `campaign.py`·`nulls.py`·`pipeline.py` 는 들어 있으니 **건드리지 않는다**.
3. **단계는 앞으로만 간다**(`program.set_phase`). `final` 로 넘기면 연구를 다시 못 한다. 그래서 R4 를 먼저 닫고 결선은 한 번만 한다.

### 단계 1 — 도구 만들기 (약 반나절, 원장 시도 0)

**1.1 실험 블록 `clock_entry_utc`** — `src/btc_quant/strategy/blocks/experimental/clock.py`

- 정의: `True@t` ⇔ 봉 t 의 **종료 시각**(t + 봉 길이)이 UTC `hour:minute` 과 같다. 봉 길이는 기존 `bar_delta(bars.index, ctx)` 로 구한다(`session_kst` 와 같은 방식). 워밍업 없음.
- 파라미터 2개, 격자(수용 검사용, 사전 선언): `hour` [0, 12, 21], `minute` [0, 5, 30]. 이번 주기에 쓰는 값은 (21, 0) 과 (0, 5) 뿐. 12시·30분은 격자 요건(값 3~5개)을 채우는 자리일 뿐이고 **쓰면 새 시도**다.
- `register_experimental(kind="entry", …, max_tf_min=60, tf_note="벽시계 시각 블록 — 4시간 봉은 종료 시각이 0/4/8/12/16/20시뿐")`, `live_ready=True`, `requires=()`, `lookback_bars=1`.
- 근거 문자열에 메커니즘 두 개(C1 휴장 시간 위험 프리미엄 / C4 09시 봇 청산)와 출처, 노출 표기(외부 문헌, 잠금·Val 노출 없음. 단 "09시에 변동이 몰린다"는 K-P0-3 은 노출 관찰이라 동기로만)를 적는다.
- 테스트 `tests/test_block_clock.py`: 1시간 봉에서 (21,0) 은 하루 정확히 1번·종료 시각 21:00Z / 5분 봉에서 (0,5) 는 00:00~00:05 봉 1번 / 결측 봉이 있어도 시각 기준 / 4시간 봉은 스펙 검증에서 거부 / 미래 변조·절단 불변. `acceptance_check("clock_entry_utc")` 통과, `docs/BLOCKS.md` 표에 `experimental` 행 추가.
- 수용 검사가 "5분 중앙 격자 신호 비율 0.1~60%"를 요구한다: (12, 5) 는 하루 1/288 = 0.35% 로 통과한다. 통과하지 못하면 블록 정의를 바꾸지 말고 원인을 적고 멈춘다.

### 단계 4 — 트랙 F: 변동성 조절 (계열 `vol_breakout`, 최대 원장 시도 4, Val 최대 1)

기존 후보의 결선 증거를 깎는 계열이므로(§1.1) 단계마다 문을 둔다.

**F-1 보고용 계산 (탐색 기록 1건)**
1. 먼저 MCP `log_exploration(family="vol_breakout", description="기존 T1 후보 개발 구간 일간 수익에 변동성 목표 배수(30일, 상한 1)를 곱한 보고용 계산 1건", configs_evaluated=1, segment="dev")`.
2. 계산(개발 구간만, `DataAccess().read("dev", …)` 와 빠른 엔진으로 후보 스펙을 다시 돌려 포트폴리오 MTM 일간 수익을 얻는다 — 원장에 쓰지 않는 순수 계산. 스크립트는 `research/program/scripts/r4f_vol_overlay.py` 에 남긴다):
   - 배수 `w_d = min(1, σ* ÷ σ_{d-1})`, `σ_{d-1}` = 전일까지 30일 일간 수익(동일 비중 3코인 보유 수익) 표준편차, `σ*` = **개발 구간 첫 365일의 σ 중앙값**(그 뒤 고정). 첫 365일은 비교에서 제외.
   - 원래 수익과 `w_d ×` 수익의 Sharpe·Calmar·최대 낙폭·최악 월, 평균 배수(= 평균 노출)를 표로.
   - **함께 볼 대조**: 평균 노출이 같은 **고정 배수**(상수 = 평균 `w`)의 Calmar. 변동성 타이밍이 "그냥 적게 들어서" 좋아 보이는 것인지 가른다.
3. 사전 규칙: `w_d` 판의 Calmar 가 원래 **그리고** 고정 배수 대조보다 높고 Sharpe 가 원래의 0.95배 이상일 때만 F-2 로 간다. 아니면 트랙 F 종료.
4. 리포트 `research/reports/r4_vol_overlay_<날짜>.md`(개발 구간 수치만, 표본 일수 표기).

**F-2 실험 필터 + 선별 (원장 시도 1)** — F-1 을 통과했을 때만
- 블록 `vol_cap(window, max_pct)` (`experimental/vol_cap.py`): 기존 `vol_regime` 과 같은 실현 변동성·같은 7일 순위 창에서 백분위 **≤ max_pct** 일 때 True. 격자 window [12, 24, 48], max_pct [0.5, 0.67, 0.8]. 쓰는 값은 (48, 0.67) 하나. 테스트·수용 검사·BLOCKS.md.
- 선별 템플릿 `screens/r4f_vol_breakout_volcap_4h_u3_screen.yaml`: 4시간, 3코인 풀링, `donchian_breakout(48)` + `vol_cap(48, 0.67)`, `stratify: hour_vol`(기본), 가설은 `lessons_derive_hypothesis` 로 camp-000034 의 사실에서 파생(계열 상속). 사건 ≥ 300 미달이면 종료.

**F-3 캠페인 (원장 시도 2)** — 선별 통과 시만
- camp-000034 와 **같은 청산·크기**(손절 2 ATR, 익절 1.5/3 ATR, 최대 보유 1440분, 절반 크기)에 필터만 추가. 스펙 2개.
