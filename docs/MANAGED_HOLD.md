# 위험 관리 보유 (managed_hold) — 설계 준비 (사용자 결정 "B", 2026-11-10)

> **상태: 준비만.** 블록·엔진 표현·템플릿·평가 도구만 만들었다. **선별·캠페인은 실행하지 않았다**(원장 시도 0, Val 사용 0).
> 진행 중인 관문 검토가 §5 의 질문에 답한 뒤에만 실행한다. 이 문서는 관문을 바꾸지 않는다 — 관문 관련 내용은 모두 **검토용 질문**이다.

## 1. 목적

지금까지의 연구(사이클 1~4)는 "짧은 지평의 엣지"(진입 신호가 무작위보다 나은가)를 찾았다. 사용자 결정 B 는 목표를 바꾼다:

- **기본은 동일 비중 3코인 바구니(BTC/XRP/ETH-KRW) 보유**, 자산별로 **장기 추세가 꺼지면 현금**(또는 축소)으로.
- 성공 = 매수보유(B&H) 대비 **낙폭 축소**와 **위험 조정 수익(Sharpe) 개선**. 높은 거래 빈도·독립 엣지가 목적이 아니다.
- 선택: 정기 적립(DCA, 주기마다 고정 KRW 투입).

메커니즘(research/knowledge/mechanisms.md M3 의 장기판): 크립토 하락 추세는 추세 추종 자금 유출과 레버리지 청산 연쇄로 길게
이어지는 경향이 있다(시계열 모멘텀·이동평균 타이밍 문헌). 느린 EMA 아래에서 현금으로 있으면 깊은 낙폭의 일부를 피하는 대신,
반등 초기와 횡보장의 잦은 왕복에서 비용(상승 포착 손실·거래 비용)을 낸다. 상대방: 하락 추세 초기에 계속 사는 매수자, 늦게 파는 보유자.

## 2. 구현 — "기본 롱 / 필터 청산"을 기존 엔진 의미론으로

### 2.1 기존 스펙으로 표현 가능한가 → **예 (엔진 변경 없음)**

ENGINE_SPEC 상태 기계(포지션 1개, 롱 온리)로 다음과 같이 표현된다.

| 요소 | 값 | 의미 |
|---|---|---|
| 진입 블록 | `trend_ema_4h(span, band_bp)` — **상태형**, 추세 중 계속 True | 무포지션이면 다음 4h 경계 시가에 진입 → "추세 동안 보유" |
| 신호 청산 | `trend_ema_off(span, band_bp)` (진입과 같은 값, `match_entry`) | 종가 < EMA·(1−band) 인 4h 봉이 닫히면 다음 경계 시가에 청산 |
| SL / TP | 고정 % 50 / 100000 | 사실상 발동하지 않는 재난용 상한 (스펙상 SL/TP 는 필수) |
| max_hold | 1800일(2,592,000분, 240의 배수) | Dev(≈1,765일)보다 길어 만기 청산이 일어나지 않음 |
| 재진입 | 엔진 쿨다운 | 청산 후 4h 봉 1개를 건너뛴 뒤 추세가 다시 켜져 있으면 재진입 |
| 바구니 | `universe: [BTC, XRP, ETH]`, 동일 고정 슬리브 1/3 | 셋 다 켜져 있으면 = 동일 비중 B&H, 자산별로 독립적으로 현금화 |
| 일간 수익 | MTM (PLAN D18, gates.yaml `evaluation.daily_returns: mtm`) | 장기 보유 포지션도 매일 평가 — 실현 기준이면 수익이 청산일에 몰려 지표가 왜곡된다 |

`band_bp > 0` 은 히스테리시스(진입은 EMA 위 band, 청산은 EMA 아래 band) — EMA 근처의 잦은 왕복 비용을 줄인다.

### 2.2 추가한 최소 기능 (하위 호환)

1. **실험 블록** `src/btc_quant/strategy/blocks/experimental/trend_state.py`
   - `trend_ema_4h` (entry): `close_t > EMA(close, span)_t · (1 + band_bp/1e4)`, 앞 span 봉 False.
   - `trend_ema_off` (exit_signal): `close_t < EMA(close, span)_t · (1 − band_bp/1e4)`.
   - 격자 span [42, 90, 180, 360] (4h: 7/15/30/60일), band_bp [0, 50, 100, 200]. `acceptance_check` 통과(2026-11-10),
     docs/BLOCKS.md 행(상태 experimental). 실험 블록을 쓴 후보는 잠금 요청 전 사람 검토 필수.
2. **캠페인 템플릿 `signal_exit`** (`research/campaign.py`) — 지금까지 스펙은 신호 청산을 지원했지만 캠페인 템플릿은 표현할 수 없었다.
   `signal_exit: {block, grid(값 1개씩), match_entry: [param…]}`. 생략하면 기존과 완전히 같다(스펙·해시·호출). 격자를 넓히지 않아
   스펙 수·예산·시도 수가 그대로다. 신호 청산 파라미터는 n_params 에 포함(보수적, 2+3+2 = 7 ≤ 8).
3. **파이프라인 수정** (`Pipeline.dev_sleeves`): Dev 재계산이 스펙의 신호 청산을 쓰도록 했다. 이전에는 `SignalCache.prepared(entry,
   filters)` 가 신호 청산을 무시했다 — 템플릿으로 신호 청산 스펙을 만들 수 없었으므로 기존 캠페인 결과에는 영향이 없다.
   (G0 인과 검사·견고성·페이퍼·전진은 이미 `spec.exit.signal_exit` 를 썼다.)
4. **DCA 오버레이** `src/btc_quant/research/managed_hold.py` — §3.

테스트: `tests/test_managed_hold.py` (블록 수식·히스테리시스, 템플릿 검증, 엔진에서 "추세 동안 보유"·신호 청산만으로 나감, 캠페인 경로 =
`run_fast`, 캠페인 결과 = 파이프라인 Dev 재계산, DCA 손계산, 저장소 템플릿 파싱).

### 2.3 표현할 수 없는 것 (질문으로 남김)

- **"축소"(부분 현금화)**: 엔진은 포지션 1개·진입 시 고정 크기(`sizing.entry_fraction`)다. "추세 약화 시 50%로 줄이기" 같은 동적
  비중은 지원하지 않는다. 근사: 두 개의 독립 슬리브(예: 절반은 무조건 보유 = B&H, 절반은 managed_hold)를 포트폴리오 수준에서 섞기
  — 일간 수익 선형 결합이라 사후 계산은 쉽지만, 지금 캠페인·관문 구조(스펙 하나 = 시도 하나)에는 없다.
- **바구니 수준 필터**(한 자산의 추세로 셋 다 청산)·자산 간 재분배(꺼진 자산 몫을 켜진 자산에): 슬리브는 독립·고정 1/3 이다.
- **낙폭 기준 청산**(고점 대비 −X%): 블록 하나로 표현 가능하지만(신호 청산 + 같은 문턱의 재진입 필터) 합성 5분봉 수용 검사의
  비퇴화(1~99%) 조건을 큰 낙폭 문턱이 넘기 어렵다 — 이번에는 EMA 규칙만 만들었다. 필요하면 변동성 단위 문턱으로 설계.

## 3. 정기 적립 (DCA)

엔진·관문은 비율 수익(시간가중, TWR) 위에서 돈다. 고정 KRW 적립은 **현금 흐름**이라 Sharpe·MDD(TWR)를 바꾸지 않고 금액가중
결과(최종 평가액, IRR)만 바꾼다. 그래서 엔진 기능이 아니라 일간 수익 위의 오버레이로 계산한다(`managed_hold.dca_overlay`):

- 각 주기(주/월)의 첫 날 시작에 c 원 투입 → 그날 전략 상태 그대로(보유 중이면 같은 비중 매수, 현금이면 대기) → `V ← V·(1+r_d)`.
- 적립분 매수 비용 `buy_cost` 는 보유 비중만큼 적립금에서 뺀다(현금 상태 적립은 다음 진입 때 엔진 비용에 이미 포함된다고 근사).
- 비교: 같은 일정의 DCA-B&H(`dca_compare`): 최종 평가액 비, IRR 차이. **보고 전용** — 어떤 관문도 쓰지 않는다.

## 4. "성공"의 정의 (B&H 대비)

동일 비중 3코인 B&H 일간 수익(`universe.buy_hold_universe`)이 이미 모든 캠페인 결과·원장에 들어간다(`metrics.benchmark_metrics`).
managed_hold 의 1차 판단 지표(제안):

| 축 | 지표 (기존 키) | 제안 기준 (검토 질문) |
|---|---|---|
| 낙폭 축소 | `max_dd` / `bh_max_dd`, `bh_dd1..3_strategy_return`(B&H 최악 낙폭 구간 동안 전략 수익) | MDD 비 ≤ 0.6, 최악 B&H 낙폭 3구간 모두 전략 손실 < B&H 손실의 절반 |
| 위험 조정 수익 | `sharpe_w`, `sharpe_minus_bh`, `downside_dev` (Sortino/Calmar 는 파생) | `sharpe_minus_bh > 0` (primary·grade 비용 모두) |
| 포착 비율 | `up_capture`, `down_capture`, `up_regime_capture`, `down_regime_capture` | 하락 포착 < 0.5, 상승 포착 > 0.5 — "보험료"(상승 포착 손실)를 명시적으로 본다 |
| 비용·회전 | `n_trades`(전환 수), `trades_per_day`, gross vs net | 전환당 비용 × 전환 수가 낙폭 축소 효과보다 작음 |
| 노출 | `exposure_time`, `exposure_days` | 보고 (추세 on 비율과 비슷해야 정상) |
| 견고성 | 인접 span·band 결과, 자산별 결과, 연도별(2021 강세/2022 약세) | 한 국면(2022)만으로 성립하지 않을 것 |

함정: 절대 Sharpe 는 바구니의 **베타(상승 표류)** 를 그대로 담는다. "Sharpe > 0" 은 B&H 도 통과할 수 있으므로 managed_hold 에서는
**B&H 대비 차이**가 증거다.

## 6. 열린 문제 (구현)

- **EMA 워밍업**: 정확 재현(초기값 잔존 가중치 ≤ 1e-12)에 4h span 180 은 ≈ 2,490봉(415일)이 필요하지만 페이퍼·전진 REST 워밍업 상한은
  120일(720봉, `paper.bars.MAX_WARMUP_DAYS`). 상한에서 잔존 가중치 ≈ (1−2/181)^720 ≈ 3.5e-4 — EMA 바로 근처의 비교만 드물게 달라질
  수 있다. 백테스트(Dev 전체 이력)에는 영향 없음. 페이퍼 전에 상한 상향 또는 SMA 변형(유한 창) 검토.
- **갭 위험**: 4h 결정이라 급락(수 시간 내 −20%)은 다음 경계까지 피하지 못한다. SL 50% 는 재난용일 뿐 — 이 위험은 MDD 비교에 그대로 나타난다.
- 신호 청산 후 쿨다운 봉 1개 — 의도된 엔진 규칙(같은 봉 재진입 방지).
