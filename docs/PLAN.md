## 1. 실행 규칙 (단순, 고정)

모든 전략이 공유하는 실행 규칙. 전략마다 다른 것은 "언제 들어가고 언제 나오나" 뿐이다.

| 규칙 | 내용 |
|---|---|
| 거래 시간 | **24시간**. 시간대 필터(`session_kst`)는 후보 블록일 뿐, 기여도 분석을 통과할 때만 사용 |
| 포지션 | 최대 1개(사다리면 사다리 1개 = 분할 최대 N개), 롱 온리 |
| 진입 | 5분봉 종가에서 신호 확정 → 다음 1분봉 시가에 **가용 자금 전액 시장가** (선택: `sizing.entry_fraction` 일부만, 또는 분할 매수 사다리 — D16, ENGINE_SPEC "부분 사이징·분할 매수") |
| 청산 감시 | 1분 단위 경로(백테스트: 1분봉 high/low, 실시간: 체결 스트림) |
| 청산 우선순위 | 손절 → 익절 → 신호 청산 → 최대 보유 시간 |
| 청산 체결 | 모든 청산은 트리거 후 시장가 매도: 기준가 × (1 − 스프레드/2 − 슬리피지) |
| 손절 기준가 | 손절가. **시가가 이미 손절가 아래면 시가** (갭) |
| 익절 기준가 | 고가가 익절가 + 1틱 이상일 때 익절가 (갭 상승도 익절가로 보수 처리) |
| 상세 | `docs/ENGINE_SPEC.md` |
| 동일 봉 동시 도달 | 손절 (사다리: 같은 봉에서 체결된 분할은 그 봉에서 익절하지 않고 손절은 적용) |
| 재진입 | 청산 후 1개 5분봉 대기 |
| 비용 | 코인원: 수수료 0% + 스프레드 + 슬리피지 / 업비트 대체 시나리오: 0.05%×2 + 스프레드 + 슬리피지 (각 base / conservative / stress) |
| 주문 제약 | 최소 5,000원, 업비트 호가 단위·수량 단위 |

## 2. 데이터

### 2.1 분할 (고정, 변경은 사람만)

```
2021-01 ─────────── 개발 Dev (약 4년 10개월) ───────────┬── 검증 Val ──┬── 잠금 Lockbox ──┬── Forward
                                                       │ 2025-11~04  │  2026-05~11-08   │ 이후 실시간
                                                       │   6개월      │     6개월         │ (페이퍼 기간)
```
- 잠금 구간: 데이터 접근 계층이 기본 차단 + hook이 경로 차단. 개봉은 사람 승인 명령만.
- Forward: 오늘 이후 쌓이는 데이터. 최종 판정의 마지막 단계(페이퍼).

### 2.2 최근 데이터 가중 (D1)
- 기준 지표(일간 Sharpe)를 **지수 가중**으로 계산: 반감기 12개월 (Dev 끝 기준).
  - 1년 전 하루 = 오늘 하루의 ½, 2년 전 = ¼. 유효 표본(Kish) ≈ 950일 (전체 Dev 약 1,760일).
- 추가 필수 조건: **Dev 최근 12개월만 따로 봐도 Sharpe > 0** (2021 불장에서만 통한 전략 차단).
- 연도별 성과표는 항상 리포트에 포함 (가중으로 가려지는 붕괴 구간 확인).
- 반감기는 지금 고정. 결과 보고 바꾸지 않는다.

### 2.3 품질·재현성
- 품질 검사 실패 구간(점검 공백 등)이 포함된 거래 윈도는 제외.
- 실험마다 **데이터 스냅샷 해시 + 코드 커밋 + 스펙 해시** 기록 → 같은 입력이면 같은 결과.
- 수수료·호가 단위 등 시장 규칙은 `config/`에 버전 관리.

## 3. 전략 풀

### 3.1 구성 = 진입 1 + 필터 0~2 + 청산 3요소(+선택적 신호 청산)
- **복잡도 상한**: 필터 최대 2개, 파라미터 총 8개 이하(청산 3개 포함).
- 블록은 검증된 Python 함수, 전략은 블록 조합 스펙(YAML).

```yaml
id: brk_donchian
version: 1
entry:   {block: donchian_breakout, params: {lookback: 48}}
filters:
  - {block: vol_regime, params: {min_pct: 0.33}}
exit:
  stop_loss_pct: 0.7
  take_profit_pct: 0.9
  max_hold_min: 90
  signal_exit: null
```

## 4. 백테스트 엔진 — 2종 대조

| 엔진 | 방식 | 용도 |
|---|---|---|
| **빠른 엔진** | numpy 벡터화 | 캠페인 격자 전수 실행 (수천 조합) |
| **기준 엔진** | 봉 단위 이벤트 루프, 읽으면 바로 검증 가능한 코드 | 최종 후보 재실행 + **그대로 페이퍼 엔진이 됨** |

- **차등 테스트**: 무작위 스펙 수백 개를 두 엔진으로 돌려 거래 목록이 일치하는지 자동 비교 (CI).

- 결과적으로 "백테스트 코드 = 페이퍼 코드"가 보장된다.

## 5. 규칙을 고르는 과정 — 연구 캠페인

### 5.1 캠페인 절차

```
① 가설 사전등록 ─▶ ② 격자·예산 고정 ─▶ ③ 빠른 엔진 전수 실행 ─▶ ④ 관문 G0~G5 (Dev)
       │                                                              │
       │          ⑦ 리포트·원장 기록 ◀─ ⑥ 잠금 G7 ◀─ ⑤ 검증 G6 (Val) ◀─┘ (상위 소수만)
       └──── 실패도 그대로 기록. 다음 가설은 원장을 읽고 세운다.
```
- ① 가설: 한 문장 + 근거(예: Phase 0 결과) + 성공 기준.
- ② 격자: 파라미터별 3~5개 값, 총 조합 수 = 시도 예산(예: ≤ 2,000). 실행 전에 원장에 기록.
- 캠페인 끝나면 격자를 넓혀 "다시 해보기"는 **새 캠페인**(시도 횟수 누적).

### 5.2 관문 (수치는 지금 고정)

| 관문 | 구간 | 통과 조건 |
|---|---|---|
| **G0 무결성** | — | 스키마, 미래참조 테스트, 복잡도 상한 |
| **G1 표본** | Dev | 거래 ≥ 300회, Dev 최근 12개월 거래 ≥ 60회 |
| **G2 엣지** | Dev | 가중 일간 Sharpe(conservative) > 0, **같은 필터·청산 + 무작위 진입** 귀무 1,000회 대비 상위 5% |
| **G3 고원** | Dev | 격자 인접 조합들의 Sharpe 중앙값 ≥ 선택 조합의 50% |
| **G4 안정** | Dev | 6개월 롤링 창 ≥ 60% 양수, 최근 12개월 Sharpe > 0, 고정 파라미터 그대로 |
| **G5 선택편향** | Dev | **Deflated Sharpe ≥ 0.95** (원장의 *실질* 시도 횟수 사용 — 수익곡선 상관으로 군집화), 캠페인 **PBO < 0.3** |
| **기여도 분석** | Dev | 필터를 하나씩 제거 → 유의하게 나빠지지 않으면 제거 후 재실행(시도 횟수 +1) |
| **G6 검증** | Val | Sharpe(conservative) > 0, stress 비용 MDD ≤ 20%, 거래당 몬테카를로 MDD 95% ≤ 20% |
| **G7 잠금** | Lockbox | §5.3 |
| **G8 실시간** | Forward | 페이퍼 ≥ 3주 & ≥ 30거래, 실측 슬리피지 ≤ conservative 가정, 손익이 백테스트 90% 구간 안 |

G8 통과 → Promotion Review → **사람 승인** → Active.

관문 일간 수익 회계(D18): camp-000025 부터 모든 관문 입력 일간 수익은 **평가 기준(MTM)** — 보유 분할을 매 UTC 일 종가에 청산 평가(종가 × (1 − 편도 비용) × (1 − 수수료)). 실현 기준(청산일 귀속)은 보유 중 평가손을 숨긴다(떨어지는 칼 사다리 합성 예: 실현 MDD 0% vs MTM 37%). 몬테카를로 MDD95 는 포지션 재표본에 포지션 중간 최악 평가 저점을 함께 넣는다. 그 전 캠페인은 등록 시점 설정(realized) 그대로.

관문과 크기(D16): 모든 관문은 **실제 사이징**의 포트폴리오 일간 수익으로 판정한다. 낙폭 관문(G6 MDD·MC MDD95·§7)은 크기에 따라 달라지는 것이 의도(작게 운용하면 낙폭도 작다)이고, 엣지 관문(G2 같은 사이징 귀무 대비 백분위, G5 DSR/PBO)은 크기에 거의 불변이라 크기를 줄여 통과할 수 없다. G1 거래 수 = 독립 포지션(사다리) 수.

### 5.3 잠금 구간 규칙 (D4: 후보마다 1회)
후보마다 열 수 있지만, 여러 번 열수록 "잠금 구간에 맞는 후보를 고르는" 효과가 생기므로 보정한다.
- **잠금 원장**: 개봉할 때마다 후보·시각·결과를 영구 기록.
- **다중 개봉 보정 (Holm)**: k번째 개봉 후보는 잠금 구간 일평균 수익 > 0 의 p값이 누적 개봉 수 기준 Holm 보정(α=0.10)을 통과해야 함. 개봉이 쌓일수록 문턱이 높아진다.
- **상한 10회**: 10번 개봉하면 해당 잠금 구간은 은퇴 → Dev/Val로 편입, 그때까지 쌓인 Forward 데이터가 새 잠금 구간이 된다.
- 개봉은 AI가 요청, 사람이 승인.

```
Draft → Candidate → Validated → Challenger(페이퍼) → Promotion Review → Active → Retired
   └────────┴────────────┴─────────────┴──────────────── Rejected (사유와 함께 영구 보존)
```

- 교체 시 이전 버전 보존 → 즉시 롤백.

## 7. 리스크 한도 — 공식으로 고정 (D5)

값은 승격 시점에 Val 백테스트 결과로 기계적으로 계산되어 전략 버전과 함께 저장된다.

| 한도 | 공식 | 발동 시 |
|---|---|---|
| 일일 손실 | min(−3%, Val 일간 손익 1백분위) | 당일 신규 진입 중지 |
| 주간 손실 | min(−6%, Val 주간 손익 1백분위) | 그 주 중지 + 알림 |
| 누적 낙폭 | min(−12%, 몬테카를로 MDD 95백분위 × 1.2) | **전략 정지, 사람 검토** |
| 성능 저하 | 실시간 거래 손익 CUSUM이 백테스트 분포 이탈 | 전략 정지, 사람 검토 |
| 거래 폭주 | 하루 거래 > max(5, 백테스트 일평균 × 3) | 중지 |
| 데이터 지연 | 체결 수신 2분 이상 없음 | 신규 진입 중지 |
| 수수료 변경 | 거래소 수수료율이 전략 승인 시 가정과 달라짐(일일 확인) | B등급 전략 즉시 정지, 알림 |
| 가격 이상 | 업비트 vs 참조 가격(바이낸스 환산 또는 빗썸) 괴리가 평소 분포 99.9% 초과 | 중지 |
| API 오류 | 3회 연속 | 중지 |
| 수동 | 킬스위치 명령 / 텔레그램 | 즉시 중지 |

- 같은 한도를 백테스트에도 적용해 실운용과 비교 가능하게 한다.
- 분할 매수 사다리(D16): 몬테카를로 MDD 는 포지션(사다리)당 슬리브 손익을 재표본(같은 사다리 분할은 함께 움직임; D18 이후 포지션 중간 MTM 저점 포함, §7 한도의 Val 일간 수익도 MTM), 거래 폭주 한도의 거래 수는 분할 체결 수. 노출 상한 = class ③ `risk_prefs.max_exposure_per_sleeve`(기본 1.0, 사용자 결정 2026-11-10).
- 연속 손실 중지는 두지 않는다(정상적인 연패에 반응해 전략을 왜곡).

## 10b. v4 연구 체계 개선 (2026-11-09 심층 검토)
근거: 개발 구간 4.8년 기준 DSR 통과에 필요한 연 Sharpe — 실질 시도 10회 1.5~2.3, 200회 2.1~3.5, 1,000회 2.4~4.0.
청산 격자(×80)가 시도 수를 폭증시켜, 탐색할수록 아무것도 통과 못 하는 구조였음.
1. **신호 선별 단계(이벤트 스터디)**: 청산 규칙 없이 진입 신호 이후 수익 분포를 매칭 귀무와 비교 → 정보 유무·지속 시간 판단. 통과 신호만 전략화.
2. **원칙적 청산**: ATR 배수 손절·익절 + 신호 지속 시간 기반 최대 보유. 청산 패턴 4~6개로 제한.
3. **검정력 계산기**: 캠페인 등록 전 통과 가능 최소 Sharpe 제시.
4. **검증 구간 원장**: Val 평가 횟수 기록·누적 보정, 상관 군집별 대표만 Val로.
5. **전진 인큐베이션**: Validated 후보 전부를 Forward 데이터에서 매일 사후 전진 테스트 — 최종 판단의 무게중심.
   **관찰 목록**(사용자 결정 2026-11-10): G6 에서 떨어진 전략은 승격하지 않고 관문도 바꾸지 않지만, 사람이
   `config/forward_watchlist.yaml`(사람 전용)에 올리면 Forward 데이터에서 매일 관찰만 한다(forward_results state=`watchlist`).
   지표 워밍업은 페이퍼와 같은 메모리 내 REST 워밍업(잠금 구간 가격, 신호 상태만 — 저장·성과 없음), 성과는 Forward
   시작 + 1봉부터. 관찰 상태는 승격·리스크·페이퍼/실거래를 뜻하지 않는다. Val 롤링(새 val_id) 시 새 Val 에서 정식 재평가 가능.
6. **교차 거래소 계열**: 업비트(실시간 수신 가능)를 보조 데이터로 쓰는 블록, 1분 결정.
7. **거래소 간 재현·자동 견고성 묶음**: 1봉 지연, 상위 거래 제거, 연도 제외, 비용 +50%, 국면별 성과.
8. **파이프라인 자체 검증**: 합성 시장 다수로 관문 전체의 검정력·오탐률 측정.
9. **오답노트**: 사실(자동)과 해석(AI, 미검증 표시) 분리, 실패 유형 자동 분류, 파생 가설은 원 계열 시도 수에 누적, Val/잠금은 결과 코드만, 과정 실수 사후분석.

## 10c. D14 초안 — 롱 온리 국면 의존 (2026-11-10, 사람 승인 대기)
배경(사용자 결정 2026-11-10, 연구 주기 1~2B): 병목은 롱 온리의 국면 의존이다. (1) 리포트에 매수보유 기준이 없었고,
(2) 관문이 '쉬는 것'을 벌한다 — G4 는 거래 없는 6개월 창(Sharpe 0)을 실패로 세고, G6 는 하락 Val 에서 맞게 쉰 전략도
Sharpe ≤ 0 이면 떨어뜨린다. **거버넌스**: 최근 한 후보가 G6 에서 떨어졌으므로 어떤 기준 변경도 합성 보정만 근거로
하고(anti-goalpost, `params.criteria` 가 실제 캠페인 언급을 거부), 승인 이후 캠페인부터 적용되며, 이미 Val 을 쓴
스펙(같은 logic_hash)은 재평가해도 이전 결정보다 느슨해질 수 없다(파이프라인 Val 재사용 규칙 — 테스트로 고정).

| 항목 | 상태 | 내용 |
|---|---|---|
| B&H 기준 지표 | ✅ 반영(정보 전용) | `metrics.benchmark_metrics`: exposure_time/exposure_days, B&H 수익·Sharpe·MDD, 노출 맞춤 B&H, 상승/하락일 capture, 인과 30일 국면 capture, 하방편차, B&H 최악 낙폭 3구간의 전략 수익. 캠페인 결과·후보·에이전트 리포트(Dev)·MCP `get_campaign_report`. Val 비교는 사람용 리포트만 |

| 롱 온리 기준 2종 보정 | ✅ 실행 | `calibration_study --rcheck`(+ `--rcheck-variants ea_on,…`, `--rcheck-beta 60`): 견고성 국면 검사 방식(비중 0.70/0.80/0.90, `robustness.regime_mode` dominant_alpha·informational — 옵션 추가, 기본 = 현재) × G4 최근 12개월 '쉼' 변형(보정 전용 반사실), 귀무 90(국면 60·표준 30) · 필터 엣지 30 시장. 결과: 오탐 0/90 전부, S*_f 검정력 현재 관문에서 23% → 23%; exposure_aware ON 일 때만 국면 검사가 묶어 23% → 30%(+7%p). **목표(+10%p) 미달 → 제안 없음**. 근거 `research/reports/calibration_regime_check_20261110.md` |
| 탐색 시도 기록 | ✅ 반영 | MCP `log_exploration` / `research.exploration.log_exploration`: 사이드 계산을 원장 시도로(계열 N·주간 예산), Dev 만, 연구 모드 직접 호출 차단. researcher·skill 필수 규칙 |

변형이 검정력을 못 올린 이유(합성 근거, §6 docs/PARAMS.md): ① 현실적인 추세 필터(60일 EMA)는 하락 국면에서도 새서 Val
시장 참여일이 대개 25% 를 넘는다 — '쉼' 경로가 적용되는 하락 Val 이 드물다. ② 적용돼도 그 후보는 견고성 묶음의 국면 검사
(한 국면 손익 비중 > 70%)에서 떨어진다 — 롱 온리 국면 의존을 막는 또 하나의 장치. ③ 필터 전략의 G4 실패(현재 규칙 10건)에서 중립 창은
드물다(53창 중 0~12개, 중앙값 3.5) — 실패는 비중립 창의 음수 Sharpe 또는 최근 12개월 조건 몫이고, 변형이 구제한 것은 1건. 다음 검토 후보(사람 결정): 최근 12개월
조건·견고성 국면 검사의 노출 인식 여부를 같은 합성 국면 시장으로 재는 것.
