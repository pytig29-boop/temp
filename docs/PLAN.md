## 1. 실행 규칙 (단순, 고정)

모든 전략이 공유하는 실행 규칙. 전략마다 다른 것은 "언제 들어가고 언제 나오나" 뿐이다.

| 규칙 | 내용 |
|---|---|
| 거래 시간 | **24시간**. 시간대 필터(`session_kst`)는 후보 블록일 뿐, 기여도 분석을 통과할 때만 사용 |
| 포지션 | 최대 1개, 롱 온리 |
| 진입 | 5분봉 종가에서 신호 확정 → 다음 1분봉 시가에 **가용 자금 전액 시장가** |
| 청산 감시 | 1분 단위 경로(백테스트: 1분봉 high/low, 실시간: 체결 스트림) |
| 청산 우선순위 | 손절 → 익절 → 신호 청산 → 최대 보유 시간 |
| 손절 체결 | 손절가 − 슬리피지. **시가가 이미 손절가 아래면 시가 − 슬리피지** (갭) |
| 익절 체결 | 가격이 익절가를 **1틱 이상 넘어야** 체결, 체결가 = 익절가 − 슬리피지 |
| 동일 봉 동시 도달 | 손절 |
| 재진입 | 청산 후 1개 5분봉 대기 |
| 비용 | 수수료 0.05%×2 + 스프레드 + 슬리피지 (base / conservative / stress) |
| 주문 제약 | 최소 5,000원, 업비트 호가 단위·수량 단위 |

## 2. 데이터

### 2.1 분할 (고정, 변경은 사람만)

```
2021-01 ─────────── 개발 Dev (약 4년 10개월) ───────────┬── 검증 Val ──┬── 잠금 Lockbox ──┬── Forward
                                                       │ 2025-11~04  │  2026-05~11-08   │ 이후 실시간
                                                       │   6개월      │     6개월         │ (페이퍼 기간)
```
- 잠금 구간: 데이터 접근 계층이 기본 차단 + hook이 경로 차단. 개봉은 사람 승인 명령만.
- Forward: 오늘 이후 쌓이는 데이터. 최종 판정의 마지막 단계(페이퍼).

### 2.2 최근 데이터 가중 (D1)
- 기준 지표(일간 Sharpe)를 **지수 가중**으로 계산: 반감기 12개월 (Dev 끝 기준).
  - 1년 전 하루 = 오늘 하루의 ½, 2년 전 = ¼. 유효 표본 ≈ 1,050일 (전체 Dev 약 1,760일).
- 추가 필수 조건: **Dev 최근 12개월만 따로 봐도 Sharpe > 0** (2021 불장에서만 통한 전략 차단).
- 연도별 성과표는 항상 리포트에 포함 (가중으로 가려지는 붕괴 구간 확인).
- 반감기는 지금 고정. 결과 보고 바꾸지 않는다.

### 2.3 품질·재현성
- 품질 검사 실패 구간(점검 공백 등)이 포함된 거래 윈도는 제외.
- 실험마다 **데이터 스냅샷 해시 + 코드 커밋 + 스펙 해시** 기록 → 같은 입력이면 같은 결과.
- 수수료·호가 단위 등 시장 규칙은 `config/`에 버전 관리.

## 3. 전략 풀

### 3.1 구성 = 진입 1 + 필터 0~2 + 청산 3요소(+선택적 신호 청산)
- **복잡도 상한**: 파라미터 총 6개 이하.
- 블록은 검증된 Python 함수, 전략은 블록 조합 스펙(YAML).

```yaml
id: brk_donchian
version: 1
entry:   {block: donchian_breakout, params: {lookback: 48}}
filters:
  - {block: vol_regime, params: {min_pct: 0.33}}
exit:
  stop_loss_pct: 0.7
  take_profit_pct: 0.9
  max_hold_min: 90
  signal_exit: null
```

### 3.2 초기 블록

| 종류 | 블록 |
|---|---|
| 진입 · 모멘텀 | `ema_slope`, `roc_threshold`, `ema_cross_up` |
| 진입 · 돌파 | `donchian_breakout`, `atr_channel_breakout`, `range_compression_break` |
| 진입 · 평균회귀 | `bollinger_z_revert`, `rsi_oversold_bounce` |
| 진입 · 교차시장 | `binance_lead_impulse` ※ 실시간 바이낸스 데이터 확보 전에는 승격 불가 |
| 진입 · 귀무 | `random_entry` |
| 필터 | `session_kst`, `vol_regime`, `volume_z`, `trend_regime_1h`, `binance_not_dumping` ※ |
| 청산 | 고정 % TP/SL, 최대 보유 시간, (선택) `ema_cross_down` 신호 청산 |

### 3.3 AI 권한
- 스펙 조합: AI 자유 (캠페인 예산 안에서, 원장 기록)
- 새 블록: AI가 코드 + 테스트 + 미래참조 검사 갖춰 **제안** → 사람 머지
- 엔진·관문·리스크·데이터 분할: AI 수정 불가

## 4. 백테스트 엔진 — 2종 대조

| 엔진 | 방식 | 용도 |
|---|---|---|
| **빠른 엔진** | numpy 벡터화 | 캠페인 격자 전수 실행 (수천 조합) |
| **기준 엔진** | 봉 단위 이벤트 루프, 읽으면 바로 검증 가능한 코드 | 최종 후보 재실행 + **그대로 페이퍼 엔진이 됨** |

- **차등 테스트**: 무작위 스펙 수백 개를 두 엔진으로 돌려 거래 목록이 일치하는지 자동 비교 (CI).
- **미래참조 테스트**: 시점 t 이후 데이터를 무작위로 변조해도 t까지의 신호가 변하지 않아야 함 (모든 블록 필수).
- 결과적으로 "백테스트 코드 = 페이퍼 코드"가 보장된다.

## 5. 규칙을 고르는 과정 — 연구 캠페인

### 5.1 캠페인 절차

```
① 가설 사전등록 ─▶ ② 격자·예산 고정 ─▶ ③ 빠른 엔진 전수 실행 ─▶ ④ 관문 G0~G5 (Dev)
       │                                                              │
       │          ⑦ 리포트·원장 기록 ◀─ ⑥ 잠금 G7 ◀─ ⑤ 검증 G6 (Val) ◀─┘ (상위 소수만)
       └──── 실패도 그대로 기록. 다음 가설은 원장을 읽고 세운다.
```
- ① 가설: 한 문장 + 근거(예: Phase 0 결과) + 성공 기준.
- ② 격자: 파라미터별 3~5개 값, 총 조합 수 = 시도 예산(예: ≤ 2,000). 실행 전에 원장에 기록.
- 캠페인 끝나면 격자를 넓혀 "다시 해보기"는 **새 캠페인**(시도 횟수 누적).

### 5.2 관문 (수치는 지금 고정)

| 관문 | 구간 | 통과 조건 |
|---|---|---|
| **G0 무결성** | — | 스키마, 미래참조 테스트, 복잡도 상한 |
| **G1 표본** | Dev | 거래 ≥ 300회, Dev 최근 12개월 거래 ≥ 60회 |
| **G2 엣지** | Dev | 가중 일간 Sharpe(conservative) > 0, **같은 필터·청산 + 무작위 진입** 귀무 1,000회 대비 상위 5% |
| **G3 고원** | Dev | 격자 인접 조합들의 Sharpe 중앙값 ≥ 선택 조합의 50% |
| **G4 안정** | Dev | 6개월 롤링 창 ≥ 60% 양수, 최근 12개월 Sharpe > 0, 고정 파라미터 그대로 |
| **G5 선택편향** | Dev | **Deflated Sharpe ≥ 0.95** (원장의 *실질* 시도 횟수 사용 — 수익곡선 상관으로 군집화), 캠페인 **PBO < 0.3** |
| **기여도 분석** | Dev | 필터를 하나씩 제거 → 유의하게 나빠지지 않으면 제거 후 재실행(시도 횟수 +1) |
| **G6 검증** | Val | Sharpe(conservative) > 0, stress 비용 MDD ≤ 20%, 거래당 몬테카를로 MDD 95% ≤ 20% |
| **G7 잠금** | Lockbox | §5.3 |
| **G8 실시간** | Forward | 페이퍼 ≥ 3주 & ≥ 30거래, 실측 슬리피지 ≤ conservative 가정, 손익이 백테스트 90% 구간 안 |

G8 통과 → Promotion Review → **사람 승인** → Active.

### 5.3 잠금 구간 규칙 (D4: 후보마다 1회)
후보마다 열 수 있지만, 여러 번 열수록 "잠금 구간에 맞는 후보를 고르는" 효과가 생기므로 보정한다.
- **잠금 원장**: 개봉할 때마다 후보·시각·결과를 영구 기록.
- **다중 개봉 보정 (Holm)**: k번째 개봉 후보는 잠금 구간 일평균 수익 > 0 의 p값이 누적 개봉 수 기준 Holm 보정(α=0.10)을 통과해야 함. 개봉이 쌓일수록 문턱이 높아진다.
- **상한 10회**: 10번 개봉하면 해당 잠금 구간은 은퇴 → Dev/Val로 편입, 그때까지 쌓인 Forward 데이터가 새 잠금 구간이 된다.
- 개봉은 AI가 요청, 사람이 승인.

## 6. 전략 레지스트리 & 운용 슬롯

```
Draft → Candidate → Validated → Challenger(페이퍼) → Promotion Review → Active → Retired
   └────────┴────────────┴─────────────┴──────────────── Rejected (사유와 함께 영구 보존)
```
- 상태 전이는 관문 코드만, `Promotion Review → Active`는 사람 전용 명령.
- Active 1개 + Challenger 최대 3개를 같은 실시간 데이터로 동시 페이퍼 운용.
- 교체 시 이전 버전 보존 → 즉시 롤백.

## 7. 리스크 한도 — 공식으로 고정 (D5)

값은 승격 시점에 Val 백테스트 결과로 기계적으로 계산되어 전략 버전과 함께 저장된다.

| 한도 | 공식 | 발동 시 |
|---|---|---|
| 일일 손실 | min(−3%, Val 일간 손익 1백분위) | 당일 신규 진입 중지 |
| 주간 손실 | min(−6%, Val 주간 손익 1백분위) | 그 주 중지 + 알림 |
| 누적 낙폭 | min(−12%, 몬테카를로 MDD 95백분위 × 1.2) | **전략 정지, 사람 검토** |
| 성능 저하 | 실시간 거래 손익 CUSUM이 백테스트 분포 이탈 | 전략 정지, 사람 검토 |
| 거래 폭주 | 하루 거래 > max(5, 백테스트 일평균 × 3) | 중지 |
| 데이터 지연 | 체결 수신 2분 이상 없음 | 신규 진입 중지 |
| 가격 이상 | 업비트 vs 참조 가격(바이낸스 환산 또는 빗썸) 괴리가 평소 분포 99.9% 초과 | 중지 |
| API 오류 | 3회 연속 | 중지 |
| 수동 | 킬스위치 명령 / 텔레그램 | 즉시 중지 |

- 같은 한도를 백테스트에도 적용해 실운용과 비교 가능하게 한다.
- 연속 손실 중지는 두지 않는다(정상적인 연패에 반응해 전략을 왜곡).
