## 2. 전략 풀 — 블록 조합 방식

전략 = **진입 신호 1개 + 필터 0~3개 + 청산 규칙 묶음**. 블록은 검증된 Python 함수, 전략은 그 조합을 적은 스펙(YAML).

```yaml
id: brk_donchian_v3
entry:   {block: donchian_breakout, params: {lookback: 48}}
filters:
  - {block: session_kst, params: {hours: [22, 23, 0, 9]}}
  - {block: vol_regime,  params: {min_pct: 0.33}}
  - {block: binance_not_dumping, params: {lookback_min: 3, z: -2}}
exit:
  take_profit_pct: 0.9
  stop_loss_pct: 0.7
  max_hold_min: 90          # ← 보유 기간도 탐색 변수
  signal_exit: {block: ema_cross_down, params: {fast: 9, slow: 21}}
  trailing_pct: null
```

### 초기 블록 라이브러리

| 종류 | 블록 |
|---|---|
| 진입 · 모멘텀 | `ema_slope`, `roc_threshold`, `ema_cross_up`, `rsi_cross_up` |
| 진입 · 돌파 | `donchian_breakout`, `atr_channel_breakout`, `range_compression_break` |
| 진입 · 평균회귀 | `bollinger_z_revert`, `rsi_oversold_bounce`, `vwap_deviation_revert` |
| 진입 · 교차시장 | `binance_lead_impulse` (바이낸스 급등 직후) |
| 진입 · 기준선 | `random_entry` (귀무 모델, 모든 비교의 바닥) |
| 필터 | `session_kst`, `vol_regime`, `volume_z`, `trend_regime(1h EMA)`, `binance_not_dumping`, `spread_ok`(페이퍼부터) |
| 청산 | 고정 TP/SL, ATR 배수 TP/SL, 시간 청산, 트레일링, 신호 청산 |

### AI의 자유도 (이전 질문 4의 결론)
- **스펙 조합**: AI가 자유롭게 (탐색 범위·횟수는 원장에 기록)
- **새 블록 추가**: AI가 코드 + 테스트 + 미래참조 검사를 갖춰 **제안** → 사람이 머지해야 라이브러리에 등록
- **엔진·관문·리스크 코드**: AI 수정 불가

## 3. 백테스트 엔진

단일 자산·롱 온리라 엔진이 단순하다. 대규모 탐색 속도와 정확성 통제를 위해 **자체 엔진**을 기본으로 하고, 최종 후보만 **Freqtrade로 교차 검증**한다(독립 구현으로 엔진 버그 탐지).

- 결정: 5분봉 종가 / 체결: 다음 1분봉 시가 + 슬리피지
- 보유 중 경로: 1분봉 high/low, 같은 봉 TP·SL 동시 도달 → 손절
- 비용: 수수료(양방향) + 스프레드 + 슬리피지, 시나리오 base / conservative / stress
- 포지션 1개, 재진입 쿨다운, 최소 주문 5,000원, 수량 단위 반영
- 동일 스펙·데이터·코드 버전 → 동일 결과 (해시로 보장)
- 단위 테스트: 미래참조 탐지(미래 데이터 변조 시 과거 신호 불변 검사), 비용 계산, 경로 처리

## 4. 검증 장치

### 4.1 데이터 분할 (고정, 변경은 사람만)

```
2025-11 ─────────────── 개발(Dev) 8개월 ───────────────┬─ 검증(Val) 2개월 ─┬─ 잠금(Lockbox) 2개월 ─ 2026-11
                                                        │                  │  최종 1회만 개봉
                                     워크포워드 창 ◀──────┘                  │  (+ 이후 신규 데이터는
                                                                           │     자동으로 Forward 구간)
```
- 잠금 구간은 데이터 접근 계층이 기본 차단하고, hook이 경로 접근을 막는다.
- 잠금 개봉은 `btc-quant lockbox-eval <id>` — 사람 승인 플래그 필요, 개봉 기록은 영구 보존.

### 4.2 관문 (Gate) — `config/gates.yaml`에 결과 보기 전에 고정

| 관문 | 통과 조건 (초안 — 확정 필요) | 다음 상태 |
|---|---|---|
| G1 기본 | 스키마·미래참조 검사 통과, Dev 거래 ≥ 150회 | Candidate |
| G2 엣지 | Dev conservative 비용 기대값 > 0, **무작위 진입 대비 p < 0.05**, 인접 파라미터도 양수(봉우리 아닌 고원) | Candidate+ |
| G3 일반화 | 워크포워드 창 ≥ 60% 양수, Val 기대값 > 0, **Deflated Sharpe > 0.9**, **PBO < 0.3** | Validated |
| G4 견고성 | stress 비용에서 손실 제한, 월별·변동성 국면별 붕괴 없음, 몬테카를로 MDD 95% < 15% | Validated |
| G5 최종 | 잠금 구간 1회 평가에서 기대값 > 0 | Challenger(페이퍼) |
| G6 실시간 | 페이퍼 2~4주, 백테스트 대비 기대값 괴리 설명 가능, 체결 품질 OK | Promotion Review → 사람 승인 → Active |

### 4.3 과최적화 방지 장치
- **실험 원장**: 모든 백테스트 실행을 기록(스펙 해시, 데이터 버전, 코드 커밋, 비용, 지표). 지우지 않는다.
- **시도 횟수 보정**: 원장의 시도 횟수 N으로 Deflated Sharpe 계산.
- **PBO (CSCV)**: 같은 패밀리 후보들로 과최적화 확률 추정.
- **귀무 모델 순열 검정**: 같은 거래 수·보유 분포의 무작위 진입 1,000회 대비 백분위.
- **가설 사전 등록**: 실험 전 가설·평가 기준을 원장에 먼저 기록.
- **파라미터 고원 검사**: 최적점 주변 ±1 스텝 성과 분포.

## 5. 전략 레지스트리 & 운용 슬롯

```
Draft → Candidate → Validated → Challenger(페이퍼) → Promotion Review → Active → Retired
             └──────────────┴────────────┴──────────────── Rejected (사유와 함께 영구 보존)
```
- 상태 전이는 관문 코드만 수행, `Promotion Review → Active`는 사람 전용 명령.
- Active는 항상 1개. 교체 시 이전 버전 보존 → 즉시 롤백 가능.
- **Champion/Challenger**: Active와 최대 3개 Challenger를 같은 실시간 데이터로 동시 페이퍼 운용 → 동일 구간 직접 비교.

## 6. AI 연구 체계 (Claude Code 기능 활용)

| 장치 | 내용 |
|---|---|
| **MCP 서버** (FastMCP) | `list_blocks`, `get_data_summary`, `register_hypothesis`, `create_candidate`, `run_backtest`, `run_sweep`, `run_walk_forward`, `run_gates`, `query_ledger`, `compare`, `write_report`. 잠금 데이터·승격·주문·키 관련 도구는 **존재하지 않음** |
| **Skills** (`.claude/skills/`) | `research-cycle`(가설→실험→기록 절차), `candidate-review`(반대 논리 심사 양식), `block-authoring`(새 블록 + 테스트 + 미래참조 검사), `daily-report` |
| **Subagents** (`.claude/agents/`) | `researcher`(후보 생성), `skeptic`(후보를 깨뜨리려 시도), `data-steward`(품질·누락 점검) |
| **Hooks** (`.claude/settings.json`) | 승인 전략·관문·리스크 설정 쓰기 차단, 잠금 데이터 경로 읽기 차단, 모든 MCP 호출 로그 |
| **예약 실행** | 야간 연구 루프 → 아침 리포트 (클라우드 예약 작업 → VPS에서는 headless Claude Code + cron) |
| **대시보드** | 원장·전략 풀·관문 통과 현황 아티팩트 |

## 7. 운용 계층 (여기서 만들고 VPS에서 상시 실행)

| 구성 | 내용 |
|---|---|
| 실시간 수집기 | 업비트 WebSocket(체결·호가·캔들) → Parquet, 끊김 자동 재연결, 누락 REST 백필 |
| 페이퍼 엔진 | **백테스트와 같은 전략 코드**로 신호 생성, 실시간 호가를 걸어 올라가며 체결 가정, 지연 반영 |

| 성능 저하 감지 | 실시간 거래별 손익 vs 백테스트 기대 분포 (CUSUM) → 이탈 시 자동 정지 + 알림 |
| 알림 | 텔레그램: 진입/청산, 일일 리포트, 경보 |
| 배포 | Docker Compose, 헬스체크, 로그 로테이션, 데이터 백업 |
| 실거래 실행기 | **범위 밖**. 인터페이스만 정의, 별도 승인 후 구현 |

## 9. 결정이 필요한 항목

1. **관문 수치**(4.2 표) — 결과 보기 전에 확정해야 의미가 있다.
2. **리스크 한도** — 예: 일일 손실 3%(9,000원), 연속 손실 5회 시 당일 중지, 최대 포지션 100%.
3. **VPS** — 업비트 지연을 고려해 서울 리전 권장 (AWS Lightsail / Vultr / 기타).
4. **알림 채널** — 텔레그램 봇 사용 여부.
