# 알려진 함정

실제 사고는 오답노트 사후분석(`research/lessons/LESSONS.md` §과정 사후분석)에 원인·재발 방지와 함께 있다.
여기는 가설·캠페인 설계 때 확인할 체크리스트.

## 누수 (leakage)
- **P-L1 잠금 노출 지식**: Phase 0 의 시간대·변동성·선행 관찰은 Val+잠금 구간에서 나왔다(PLAN §11, PM phase0-lockbox-exposure).
  이 관찰로 만든 가설은 Dev 신호 선별로 재확인하고, 리포트에 노출을 표기. src: PLAN §11 · 잠금: 노출 · Val: 노출
- **P-L2 Val 엿보기**: G6 결과를 보고 Dev 파라미터를 바꾸면 Val 은 Dev 가 된다. 실패한 Val 은 결과 코드만 기록되며(오답노트),
  "Val 에서 이랬으니"를 해석의 근거로 쓰지 않는다. Val 사용은 원장 val_evaluations 로 누적 Holm 보정. src: PLAN §10b-4
- **P-L3 미래 참조**: `shift(-k)`, 중심 창, `bfill`, 전체 표본 정규화, 오른쪽 라벨 리샘플, 미완료 상위 시간봉. src: block-authoring skill
- **P-L4 최근 가격 추론**: 잠금 구간 가격을 기억·추론으로 쓰지 않는다(예: "2026 여름에 올랐으니"). src: research-campaign skill

## 통계
- **P-S1 시도 수 폭증**: 청산 격자 ×80 → DSR 통과 불가(실질 시도 1,000회면 연 Sharpe 2.4~4.0 필요). 청산 변형 ≤ 6,
  등록 전 검정력 계산(`btc_quant.research.power`). src: PLAN §10b, PM dsr-power-exit-grid
- **P-S2 계열 이름 바꾸기**: 실패한 아이디어를 새 family 이름으로 다시 등록하면 시도 수가 0 부터 다시 센다 = 선택편향 세탁.
  파생 가설은 `derive_hypothesis` 로 부모 계열 상속(오버라이드는 사람만). src: lessons.py
- **P-S3 귀무의 거래 수 불일치**: 신호 비율만 맞춘 무작위 진입은 더 자주 거래해 비용을 더 낸다 → 후보가 "덜 거래해서" 이김.
  귀무는 거래 수 맞춤(기본). src: research/nulls.py, PM g2-null-trade-count-bias
- **P-S4 격자 넓혀 재실행**: 같은 블록·겹치는 격자를 다시 돌리면 반복 시도다. 등록 전 `find_similar` → exact 이면 중단하거나
  새 메커니즘을 명시. src: PLAN §5.1
- **P-S5 소수 거래 의존**: 대폭락·대급등 며칠이 손익 대부분 → 상위 거래 제거·연도 제외 견고성. src: PLAN §10b-7
- **P-S6 국면 편중**: 2021 강세 / 2022 약세 / 2023~ 회복. 롱 온리는 강세장 베타를 엣지로 착각하기 쉽다 → 연도별 표, 매칭 귀무.

## 절차
- **P-P1 사전등록 순서**: 가설·격자는 실행 *전에* 원장에. 탐색용 한 번 실행도 시도다.
- **P-P2 관문 완화 금지**: 아무것도 통과 못 하면 "없음" 보고. 기준은 낮추지 않는다(PLAN §10).
- **P-P3 해석을 사실처럼**: 오답노트 해석은 unverified. 후속 캠페인 없이 "검증됨"이라 쓰지 않는다.
- **P-P4 영구 금지 규칙화**: 실패 교훈에도 범위(거래소·시간축·구간·비용)와 재검토 조건이 있다. 비용·데이터가 바뀌면 다시 본다.
